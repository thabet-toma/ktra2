## 1. المشكلة

اللوحة الحالية ليست لوحة واحدة، بل شاشة إدارة شركات حقيقية وأربع أدوات لا علاقة لها بها تحت قائمة «إدارة المنصة»:

- `components/superadmin/SuperAdminDashboard.tsx` (`SuperAdminDashboard`): صفحة طويلة تكدّس كل شيء — إحصاءات، منح صلاحية سوبر أدمن، توثيق المحاسبين، جدول الشركات، اختيار شركة المثال.
- `components/superadmin/PlatformCompanyPanel.tsx` (`PlatformCompanyPanel`): درج جانبي يخلط اشتراك خطة كترا (`Tenant.SubscriptionPlan`) مع اشتراك خدمة إدخال البيانات (`ServiceSubscription`).
- في القائمة نفسها: مركز العمليات الداخلي (15 تبويباً)، التوظيف، ملاحظات التطوير، فواتير الخدمة.
- قائمتا شركات، ومفهومان لـ«الصحة»، وتسميات خطط في الواجهة (`COMPANY_PLAN_LABELS`) تخالف الخادم (`PLAN_LABELS`).
- نقطة `/api/platform/plan-pricing/` موجودة بلا شاشة.

| الطلب | الحالة اليوم |
|---|---|
| طلب موافقة الشركة للدخول | **غير موجود** — السوبر أدمن يدخل أي شركة بصمت، بلا إذن ولا تسجيل |
| عدد الحركات والمستندات | **جزئي** — فواتير الشهر، آخر نشاط، التخزين فقط |
| حدّ التخزين | الاستهلاك محسوب (`TenantAsset`)، **لا حدّ** |
| سجل تدقيق عام | **غير موجود** — منح السوبر أدمن وتعطيل المستخدمين وتغيير الأسعار في `logger.info` فقط |
| الإيراد الشهري | غير موجود |
| إنشاء شركة من اللوحة | غير موجود (تسجيل ذاتي فقط) |

### ⚠️ خطر مسجَّل

1. `core/tenant_utils.py` (`_validate_user_tenant_access`) و`tenants/views.py` (`TenantViewSet.get_queryset`): الـsuperuser يتجاوز العضوية ويدخل أي شركة بلا إذن ولا أثر.
2. تعريف «سوبر أدمن» غير موحّد: `core/import_access.py` (`is_super_admin`) يقبل الإيميل من الإعدادات، والنقطتان أعلاه تفحصان `is_superuser` وحده.
3. محاولات الدخول الفاشلة عدّادات cache فقط (`hr/auth_api.py` — `_login_register_failure`) لا تُحفظ.

ليس نزيفاً حالياً (المستخدم الوحيد هو المالك). تعالجه SA-1 وSA-2.

## 2. المرجع الاحترافي (§1.5)

- **Google Access Approvals / Atlassian:** طلب بسبب مكتوب ← موافقة الشركة لمدة محددة ← انتهاء تلقائي وسحب في أي وقت ← كل فعلٍ يظهر في سجل الشركة باسم الموظف. **Zoho:** حتى مع الإذن، لا تصدير ولا إدارة مستخدمين ولا إعدادات أمان. **Zendesk/Google:** دخول طارئ بلا إذن بسببٍ مكتوب وإفصاح للشركة. **Salesforce:** الاستهلاك مقابل الحد، محسوب في الخلفية مع «آخر تحديث».
- **أخذنا:** دورة الطلب/الموافقة/الانتهاء · قراءة فقط افتراضياً · محظورات ثابتة حتى مع الإذن الكامل · فصل «من فعل» عن «باسم من» · شريط «أنت داخل شركة X». **نتجاوزهم:** الشركة ترى نشاط الدعم داخل سجل نشاطها العادي لا في صفحة مخفية، والإشعار بالدخول الطارئ **فوري** لا لاحق.
- **رفضنا من برومت الوكيل:** PostgreSQL وschema لكل شركة (نحن MySQL + عمود `tenant`) · subdomain لكل شركة (الشركة تُحدَّد بـ`X-Tenant-Id`) · رسوم CPU/RAM لحظية (شأن أدوات الاستضافة) · الوضع الداكن حصراً (نتبع ثيم التطبيق).

المسارات موحّدة تحت `/super-admin/*`، والمسارات القديمة (`/platform/hiring` …) تُحوَّل تلقائياً.

## 5. تدفّق الدخول للدعم

```
[السوبر أدمن] صفحة الشركة ← «طلب دخول» (سبب إلزامي، مدة، قراءة/كامل)
      │                                       │
      │                          [الشركة] إشعار + بطاقة في لوحتها
      │                          ← موافقة (قد تُقصّر المدة/تُخفّض النطاق) | رفض
      ▼                                       │
  «دخول الشركة» ◄────── إذن ساري ─────────────┘
      │  شريط أحمر: «أنت داخل شركة X — قراءة فقط — حتى 14:30» + زر خروج
      │  كل طلب يُسجَّل في ActivityLog الشركة موسوماً «دعم كترا» + رقم الإذن
      ▼
  انتهاء المدة | سحب الشركة | خروج ← يُغلق الدخول فوراً (403 على الطلب التالي)

[طارئ] «دخول طارئ» ← سبب إلزامي ← إذن 4 ساعات فوراً ← إشعار فوري للشركة + خطورة عالية
```

حالات الخطأ: طلب بلا إذن ساري ← 403 برسالة عربية ورابط «طلب دخول» · إذن قراءة + كتابة ← 403 «الإذن قراءة فقط» · محظور ثابت ← 403 «غير مسموح لفريق الدعم» · إذن انتهى أثناء العمل ← الشريط يتحوّل إلى «انتهى الإذن» مع زر خروج.
