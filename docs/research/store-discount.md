# خصمُ المتجر — بحثٌ في عقود المنصّات والشقّ القانونيّ

> قضيّة `thabet-toma/ktra2#158`. مصادرُ أوليّةٌ حصراً: توثيقُ المنصّة الرسميّ، أو
> شيفرتُها المصدريّة، أو نصُّ الجهة التنظيميّة نفسِها. كلُّ ادّعاءٍ برابط.
> **ما لم يُفتَح بنجاح لا يُثبَّت** — وُسِم صراحةً «غير متحقَّق».

**سياقُ الاستهلاك:** Django 5.1 + MySQL + DRF، واجهةُ متجرٍ عامّةٌ بلا مصادقة، وعقدُ
JSON يحمل اليوم مفتاحَ سعرٍ **واحداً** (`price`). قرارُ المالك: الخصمُ **عرضٌ لا
غير** (لا يُلزِم الفوترة إطلاقاً)، تحمله حملةٌ ذاتُ تاريخَي بدءٍ وانتهاء، ويُعرض
سعراً أصليّاً مشطوباً مع السعر المخفَّض بالأحمر. ولا مخزونَ في متجرنا ولا ارتباطَ
محاسبيّ بقرار المالك.

**نطاقُ هذه الجولة:** Shopify وWooCommerce والشقُّ القانونيّ. أمّا Salla فمحسومةٌ من
جولةٍ سابقة ومُلخَّصةٌ هنا ليقومَ الملفُّ وحدَه. **Zid وBigCommerce لم تُغطَّ.**

## ١. الحقول ودلالتُها — حرفيّاً

### Shopify — `compare_at_price`

الحقلُ يعيش على **المتغيّر** (`ProductVariant`) لا على المنتج، واسمُه
`compareAtPrice` في GraphQL و`compare_at_price` في REST وLiquid.

ومرجعُ الـAPI **لا يقول عنه شيئاً تقريباً**. هذا كلُّ ما فيه حرفيّاً:

| الحقل | التعريف | الوصفُ الحرفيّ |
|---|---|---|
| `price` | `Money!` غيرُ قابلٍ للعدم | "The price of the product variant in the default shop currency." |
| `compareAtPrice` | `Money` قابلٌ للعدم | "The compare-at price of the variant in the default shop currency." |

المصدر: [shopify.dev — ProductVariant](https://shopify.dev/docs/api/admin-graphql/latest/objects/ProductVariant)

**وهذه نتيجةٌ بذاتها:** العقدُ التقنيُّ عند Shopify **لا يحمل الدلالة**. لا شرطَ
«أكبر من»، ولا رايةَ `on_sale`، ولا ذكرَ أنّ الحقل للعرض. الدلالةُ كلُّها تعيش في
دليل التاجر لا في المخطَّط. فمن قرأ الـAPI وحدَه لن يعرف كيف يُستعمل الحقل.

ودليلُ التاجر هو الذي يحسم، بنصَّين قاطعَين:

> "set the value of the **Compare-at price** field in your Shopify admin to the
> original price of the product. Make sure that the value in the **Compare-at
> price** field is higher than the value in the **Price** field to display the
> sale price."

> "Both these amounts can be displayed on product pages and collection pages,
> but **only the sale price is displayed at checkout**."

المصدر: [help.shopify.com — Sale pricing](https://help.shopify.com/en/manual/products/details/product-pricing/sale-pricing)

الجملةُ الثانية هي **إقرارُ المنصّة نفسِها بأنّ السعرَ المقارَن عرضٌ لا غير** — لا
يبلغ السلّةَ ولا الدفع. وهذا يُصادق قرارَ المالك عندنا من مصدرٍ أوّليٍّ لا اجتهاد.

**ولا تواريخَ إطلاقاً.** Shopify **لا تُجدوِل** السعرَ المقارَن: لا حقلَ بدءٍ ولا
انتهاء. الجدولةُ عندها تعيش في محرّك الخصومات المُلزِم وحدَه — وهذا خلافٌ مع
WooCommerce وSalla، لا اتّفاق.

### WooCommerce — الرباعيّةُ الكاملة

| الحقل | النوع | الوصفُ الحرفيّ | للقراءة فقط |
|---|---|---|---|
| `price` | string | "Current product price." | **نعم** |
| `regular_price` | string | "Product regular price." | لا |
| `sale_price` | string | "Product sale price." | لا |
| `date_on_sale_from` | date-time | "Start date of sale price, in the site's timezone." | لا |
| `date_on_sale_from_gmt` | date-time | "Start date of sale price, as GMT." | لا |
| `date_on_sale_to` | date-time | "End date of sale price, in the site's timezone." | لا |
| `date_on_sale_to_gmt` | date-time | "End date of sale price, in the site's timezone." | لا |
| `on_sale` | boolean | "Shows if the product is on sale." | **نعم** |
| `price_html` | string | "Price formatted in HTML." | **نعم** |

المصدر: [`class-wc-rest-products-controller.php` — `get_item_schema()`](https://raw.githubusercontent.com/woocommerce/woocommerce/trunk/plugins/woocommerce/includes/rest-api/Controllers/Version3/class-wc-rest-products-controller.php)

> ملحوظةٌ جانبيّة تدلُّ على أنّ المخطَّط قُرئ لا نُقل: وصفُ `date_on_sale_to_gmt`
> يقول "in the site's timezone" وهو **خطأُ نسخٍ في مصدر WooCommerce نفسِه** —
> صوابُه "as GMT" كنظيره في `date_on_sale_from_gmt`.

**والبنيةُ هي المهمّة:** ثلاثةُ حقولٍ منها للقراءة فقط — `price` و`on_sale`
و`price_html`. أي أنّ **السعرَ النافذ والرايةَ مُشتقّان لا مخزَّنان**. المخزَّنُ هو
`regular_price` و`sale_price` والتاريخان لا غير.

## ٢. التواريخ والاشتقاق — أقوى إجماعٍ في البحث كلِّه

جسدُ `is_on_sale()` في WooCommerce، حرفيّاً:

```php
public function is_on_sale( $context = 'view' ) {
	if ( '' !== (string) $this->get_sale_price( $context ) && $this->get_regular_price( $context ) > $this->get_sale_price( $context ) ) {
		$on_sale = true;

		if ( $this->get_date_on_sale_from( $context ) && $this->get_date_on_sale_from( $context )->getTimestamp() > time() ) {
			$on_sale = false;
		}

		if ( $this->get_date_on_sale_to( $context ) && $this->get_date_on_sale_to( $context )->getTimestamp() < time() ) {
			$on_sale = false;
		}
	} else {
		$on_sale = false;
	}
	return 'view' === $context ? apply_filters( 'woocommerce_product_is_on_sale', $on_sale, $this ) : $on_sale;
}
```

المصدر: [`abstract-wc-product.php`](https://raw.githubusercontent.com/woocommerce/woocommerce/trunk/plugins/woocommerce/includes/abstracts/abstract-wc-product.php)

ثلاثةُ شروطٍ تتضافر: **سعرُ خصمٍ موجود** ∧ **الأصليُّ أكبرُ منه فعلاً** ∧ **الآنَ
داخلَ النافذة**.

**وحقيقتان عمليّتان تُقرَآن من هذا الجسد لا من التوثيق:**

1. **لا يُصفَّر `sale_price` عند انتهاء النافذة.** لا في `set_sale_price` ولا في أيّ
   تحقُّقٍ عند الحفظ — بحثتُ فلم أجد. القيمةُ تبقى مخزَّنةً والنافذةُ تُقيَّم **عند
   القراءة**. فالحملةُ المنتهيةُ بياناتٌ باقيةٌ ورايةٌ منطفئة، لا بياناتٌ محذوفة.
   وهذه بالضبط الشكلُ الذي يلزم تصميمَنا: صفوفُ حملةٍ محفوظة، ورايةٌ مشتقّة.
2. الاشتقاقُ قابلٌ للتجاوز بمرشّحٍ (`woocommerce_product_is_on_sale`) — أي أنّ
   WooCommerce نفسَها تعدُّ القرارَ **نقطةَ سياسةٍ واحدةً** لا شرطاً منثوراً في
   القوالب. عندنا يقابله دالّةٌ واحدة، لا شرطٌ مكرَّرٌ في كلّ مُسلسِل.

**والإجماعُ عبر المنصّات الثلاث على شرط «الأصليُّ أكبرُ فعلاً»:**

| المنصّة | الحارس | المصدر |
|---|---|---|
| WooCommerce | `regular_price > sale_price` داخلَ `is_on_sale()` | الشيفرة أعلاه |
| Salla | `is_on_sale = has_sale_price && regular_price > price` في المتصفّح | `theme-raed/src/assets/js/product.js` |
| Shopify | "Make sure that the value ... is higher than ... to display the sale price" | دليلُ التاجر |

ثلاثةٌ من ثلاثة. هذا أوثقُ ما خرج به البحث، وهو يحسم النقطةَ ٦ من التذكرة (حالاتُ
الحافّة): **الرايةُ مشتقّةٌ لا مخزَّنة، والخصمُ الصفريُّ أو السالبُ لا يُعرَض**.

أمّا Shopify فتقف خارجَ إجماع **التواريخ**: لا نافذةَ للسعر المقارَن أصلاً.

## ٣. الخصمُ على المنتج مقابلَ الخصمِ على المجموعة — وقاعدةُ الغلبة

**هذه أهمُّ نقطةٍ في التذكرة، وجوابُها ليس القاعدةَ بل غيابَها.**

### النتيجةُ الصريحة

**لا Shopify ولا WooCommerce تُوثّق قاعدةَ غلبةٍ بين خصمَي عرضٍ على المنتج نفسِه —
لأنّ أيّاً منهما لا تملك مصدرَي خصمِ عرضٍ أصلاً.** التعارضُ الذي سيصطدم به تصميمُنا
**غيرُ موجودٍ عندهما بنيويّاً**، فلا سابقةَ تُنقَل. **القاعدةُ من صنعنا نحن.**

والسببُ بنيويٌّ لا عرَضيّ. المنصّتان تفصلان الخصمَ سطحَين:

| | سطحُ العرض (على المنتج) | سطحُ الحملة (على المجموعة) |
|---|---|---|
| **Shopify** | `compareAtPrice` على `ProductVariant` — لا يبلغ الدفع | Automatic discounts / Discount Functions — **مُلزِمةٌ عند الدفع** |
| **WooCommerce** | `sale_price` على المنتج والتنويعة | كوبونات `WC_Coupon` — **مُلزِمةٌ عند الدفع**؛ ولا خصمَ تصنيفٍ في النواة أصلاً |

فالسطحُ الأوّل عرضٌ على مستوى المنتج، والثاني إلزامٌ على مستوى الحملة. لا يتنازعان
لأنّهما لا يعيشان في المكان نفسِه: أحدُهما يرسم، والآخرُ يحاسب.

**وتصميمُنا يدمج الاثنين في واحد**: حملةٌ على مستوى المجموعة، عرضٌ لا إلزام. هذا
شكلٌ **لا تملكه أيٌّ من المنصّتين**. ولذلك لن نجد القاعدةَ، وعلينا وضعُها.

### لكنّ لكلّ منصّةٍ فلسفةً في الغلبة تصلح قالباً — وهما مختلفتان

**Shopify — آليّةٌ، والأفضلُ للزبون يفوز.**

ثلاثةُ أصنافٍ من الخصم (product / order / shipping) بمصفوفةِ اندماجٍ موثَّقة. وحين
يتعذّر الاندماجُ وينطبق خصمان على الطلب أو الصنف نفسِه:

> "the best discount or combination of discounts for the customer's cart is
> always applied."

وترتيبُ التطبيق موثَّقٌ كذلك: **خصومُ المنتج أوّلاً** على الأصناف، ثمّ **خصومُ
الطلب** على المجموع بعد الأوّل، ثمّ **خصومُ الشحن** آخراً.

المصدر: [help.shopify.com — Discount combinations](https://help.shopify.com/en/manual/discounts/discount-combinations)

> تنبيهٌ على المصدر: صفحةُ `combining-discounts` تُحوّل ولا تحمل القواعد؛ الحاملُ
> هو `discount-combinations`. وصفحةُ المطوّرين
> [shopify.dev — Discounts](https://shopify.dev/docs/apps/build/discounts) تُعرّف
> الأصنافَ الثلاثة (`discountClasses`) **ولا تذكر الغلبةَ ولا الترتيبَ إطلاقاً** —
> فقاعدةُ الغلبة عند Shopify موثَّقةٌ للتاجر لا للمطوِّر.

**WooCommerce — يدويّةٌ، ومفتاحٌ يقرّره التاجر.**

النواةُ لا تُرجّح تلقائيّاً. الموضعُ الوحيدُ الذي تحسم فيه تعارضَ خصمِ المنتج مع
آليّةِ الحملة هو `validate_coupon_sale_items()`:

```php
protected function validate_coupon_sale_items( $coupon ) {
    if ( $coupon->get_exclude_sale_items() ) {
        $valid = true;
        foreach ( $this->get_items_to_validate() as $item ) {
            if ( $item->product && $item->product->is_on_sale() ) {
                $valid = false;
                break;
            }
        }
        if ( ! $valid ) {
            throw new Exception(
                sprintf(
                    esc_html__( 'Sorry, coupon "%s" is not valid for sale items.', 'woocommerce' ),
                    esc_html( $coupon->get_code() )
                ),
                110
            );
        }
    }
    return true;
}
```

المصدر: [`class-wc-discounts.php`](https://raw.githubusercontent.com/woocommerce/woocommerce/trunk/plugins/woocommerce/includes/class-wc-discounts.php)

وثلاثُ قراءاتٍ من هذا الجسد:

1. الحسمُ **رايةٌ يضبطها التاجر** (`exclude_sale_items`) لا قاعدةٌ آليّة.
2. أثرُ الرايةِ **رفضُ الكوبونِ كلِّه** برسالةِ خطأ — لا اختيارُ الأعمق. فالغلبةُ
   عند WooCommerce **إقصاءٌ لا مفاضلة**.
3. والافتراضُ حين تُطفَأ الرايةُ هو **التراكم**: الكوبون يُحتسَب فوقَ السعر المخفَّض
   لا فوقَ الأصليّ. (ملحوظة: مسارُ الاحتساب نفسُه لم أفتحه في هذه الجولة؛ الاستدلالُ
   من أنّ `is_on_sale()` هو معيارُ الاستثناء الوحيد — **درجةُ ثقةٍ متوسّطة**.)

### الخلاصةُ لصاحب القرار

| | Shopify | WooCommerce |
|---|---|---|
| من يقرّر؟ | المنصّة، آليّاً | التاجر، بمفتاح |
| ما القاعدة؟ | الأفضلُ للزبون | إقصاءُ الكوبون كلِّه، أو التراكم |
| الافتراض | مفاضلةٌ دائماً | تراكمٌ ما لم يُستثنَ |

**اختلافٌ صريحٌ يُعلَّم قرارَ مالك.** وأميل إلى قالب Shopify لخصمِ عرضٍ مثلِ خصمِنا:
ما دام لا شيءَ مُلزِماً، فـ«الأعمقُ يفوز» سطرٌ واحدٌ من الكود، ولا يظلم الزبونَ
أبداً، ولا يحتاج واجهةً يضبطها التاجر — بينما مفتاحُ WooCommerce يشتري مرونةً ثمنُها
شاشةُ إعداداتٍ ودعمٌ فنّيّ. **وينبغي أن نُسجّلها قراراً لنا مُستنِداً إلى مبدأ
Shopify، لا أن ندّعيَ أنّها قاعدةٌ منقولةٌ في أسعار العرض.**

**وتوصيةٌ ملازمة:** يجب أن يحمل الـJSON **الفائزَ محسوماً وحدَه**، لا قائمةَ حملاتٍ
يحلّها العميل. الحسمُ في الخادم مرّةً — وإلّا صار لدينا نسختان من القاعدة تفترقان،
وهو عطبٌ تكرّر في هذا المستودع من قبل.

## ٤. العرضُ البصريّ والترميز

### WooCommerce — النواةُ تُرمِّز ولا تُلوِّن

```php
function wc_format_sale_price( $regular_price, $sale_price ) {
	$formatted_regular_price = is_numeric( $regular_price ) ? wc_price( $regular_price ) : $regular_price;
	$formatted_sale_price    = is_numeric( $sale_price ) ? wc_price( $sale_price ) : $sale_price;

	// Strikethrough pricing.
	$price = '<del aria-hidden="true">' . $formatted_regular_price . '</del> ';

	// For accessibility (a11y) we'll also display that information to screen readers.
	$price .= '<span class="screen-reader-text">';
	$price .= esc_html( sprintf( __( 'Original price was: %s.', 'woocommerce' ), wp_strip_all_tags( $formatted_regular_price ) ) );
	$price .= '</span>';

	// Add the sale price.
	$price .= '<ins aria-hidden="true">' . $formatted_sale_price . '</ins>';

	$price .= '<span class="screen-reader-text">';
	$price .= esc_html( sprintf( __( 'Current price is: %s.', 'woocommerce' ), wp_strip_all_tags( $formatted_sale_price ) ) );
	$price .= '</span>';

	return apply_filters( 'woocommerce_format_sale_price', $price, $regular_price, $sale_price );
}
```

المصدر: [`wc-formatting-functions.php`](https://raw.githubusercontent.com/woocommerce/woocommerce/trunk/plugins/woocommerce/includes/wc-formatting-functions.php)

أربعُ ملاحظاتٍ تخصّنا:

1. **الترميزُ دلاليّ**: `<del>` و`<ins>` — لا `<span>` بشطبِ CSS. وSalla تفعل العكسَ
   (`line-through` بخاصّيّة CSS). **خلافٌ في الترميز.**
2. **والوسمان مخفيّان عن قارئ الشاشة** (`aria-hidden="true"`)، ويُعوَّض عنهما بنصٍّ
   صريح: «Original price was: …» و«Current price is: …». هذه **المعالجةُ الوحيدةُ
   الواعيةُ بالوصول في البحث كلِّه** — Salla لا تقدّم مقابلاً لها. أوصي بتبنّيها؛
   فهي أفضلُ بلا ثمن.
3. **الترتيبُ في DOM: المشطوبُ أوّلاً ثمّ المخفَّض.** وSalla عكسُه تماماً (المخفَّضُ
   أوّلاً). **خلافٌ صريح** — ويهمّنا لأنّ متجرنا RTL، وترتيبُ Salla يضع الجديدَ
   يميناً.
4. **النواةُ لا تفرض لوناً إطلاقاً.** اللونُ متروكٌ للقالب.

### Shopify

لا شيء. لا مرجعُ الـAPI ولا دليلُ التاجر يصف تنسيقاً؛ الدليلُ يكتفي بأنّ الظهور
«depends on your theme»، وأنّ القوالبَ قد تضيف "a badge with a message or percentage
off". ومسارُ توثيقِ القوالب الذي جرّبتُه
(`/docs/storefronts/themes/architecture/templates/product/sale-prices`) **رجع 404** —
فلا مصدرَ أوّليَّ عند Shopify للمعالجة البصريّة.

### الحصيلة

| | Shopify | WooCommerce | Salla |
|---|---|---|---|
| ترميزُ الشطب | غيرُ موثَّق | `<del>` دلاليّ | `line-through` بـCSS |
| نصٌّ لقارئ الشاشة | لا | **نعم** | لا |
| الترتيبُ في DOM | غيرُ موثَّق | مشطوبٌ ثمّ مخفَّض | مخفَّضٌ ثمّ مشطوب |
| لونُ المشطوب | غيرُ موثَّق | غيرُ مفروض | رماديّ (gray-400/500) |
| لونُ المخفَّض | غيرُ موثَّق | غيرُ مفروض | أحمر (`text-red-800`) |

**لا إجماعَ على اللون ولا على الترتيب.** Salla هي العُرفُ الوحيدُ المُسنَد، وهو يوافق
تصميمَ المالك **بشرط** أن يقع الأحمرُ على المخفَّض لا على المشطوب.

## ٥. الشارةُ ونسبةُ الخصم

- **Salla**: نسبةٌ مئويّةٌ محسوبة، بصيغة «خصم 20%»، وبحارس `percent > 0`. ولا مبلغَ
  توفيرٍ في أيّ مصدرٍ رسميّ. وترسل `discount_percentage` مهيَّأً نصّاً ولا يعرضه
  القالب.
- **Shopify**: لا حقلَ شارةٍ ولا نسبةٍ في العقد. الدليلُ يذكر أنّ **القوالب** قد
  تعرض "a badge with a message or percentage off" — أي أنّ الشارةَ شأنُ القالب لا
  شأنُ المنصّة.
- **WooCommerce**: `wc_format_sale_price` لا تُصدِر شارةً ولا نسبةً إطلاقاً. لا حقلَ
  نسبةٍ في مخطَّط REST.

**فـSalla وحدَها ترسل النسبةَ جاهزةً؛ والمنصّتان الأخريان لا ترسلان شيئاً.** ومع
ذلك أوصي بإرسالها: حسابُها في الخادم مرّةً أرخصُ وأدقُّ من إعادةِ اشتقاقها في كلّ
عميلٍ بحسابٍ عائم، ولا يكلّف شيئاً. **ولا تُرسَل قطُّ ما لم تكن موجبة.**

## ٦. الشقُّ القانونيّ — هل يجب أن يكون السعرُ المشطوب قد بيع به فعلاً؟

### الاتّحاد الأوروبيّ — **نعم، وبعددٍ صريح**

المادّةُ 6a من توجيه بيان الأسعار 98/6/EC، المضافةُ بتوجيه Omnibus (EU) 2019/2161،
النافذةُ منذ **28 مايو 2022**:

> "traders are obliged, when offering a discount, to indicate the lowest price
> applied to the item **at least 30 days** before the announcement of the price
> reduction."

> "Price reduction claims such as 'was € 50, now € 25' can be misleading if the
> initial selling price (known as 'anchor price') has been inflated."

المصدر: [Your Europe — Unfair pricing (europa.eu)](https://europa.eu/youreurope/citizens/consumers/unfair-treatment/unfair-pricing/index_en.htm)

وإرشادُ المفوّضيّة المفصَّل هو
[CELEX 52021XC1229(06)](https://eur-lex.europa.eu/legal-content/EN/ALL/?uri=CELEX:52021XC1229(06))،
ويتضمّن خياراتٍ تنظيميّةً للدول الأعضاء في السلع سريعةِ التلف، والسلعِ المعروضةِ
أقلَّ من 30 يوماً، والتخفيضاتِ المتصاعدة.

> **حدُّ التحقُّق:** كلُّ محاولاتي لفتح نصّ EUR-Lex مباشرةً رجعت **بصفحةٍ فارغة**
> (النسخةُ المدمجة `01998L0006-20210528` بصيغتَي ELI وHTML). النصُّ المقتبَسُ أعلاه
> من `europa.eu` وهو **مصدرٌ اتّحاديٌّ رسميّ**، لكنّه صياغةٌ موجَّهةٌ للمستهلك لا
> نصُّ المادّة. **رقمُ الثلاثين يوماً ومبدأُ «أدنى سعرٍ مطبَّق» مؤكَّدان؛ أمّا
> صياغةُ الاستثناءات فلم تُقرَأ من النصّ التشريعيّ.**

### المملكة المتّحدة — **لم أجد قاعدةً عدديّةً في الإرشاد النافذ**

بحثتُ في إرشاد هيئةِ المنافسة والأسواق (CMA) الصادرِ بموجب قانون DMCC لسنة 2024:

- **CMA209 «Price transparency»** — الملخَّصُ الرسميُّ بصيغة HTML **لا يتناول
  التسعيرَ المرجعيَّ إطلاقاً**. يتناول: السعرَ الكلّيَّ مقدَّماً، والرسومَ الإلزاميّة،
  وأسعارَ «ابتداءً من»، و«drip pricing» و«partitioned pricing». والعقوبةُ تصل إلى
  10% من رقم الأعمال أو 300 ألف جنيه أيّهما أكبر.
  [gov.uk — CMA209](https://www.gov.uk/government/publications/price-transparency-cma209)
- **CMA207 «Understanding unfair commercial practices: examples»** — أمثلتُه الخمسة
  (عدّاداتُ السيارات، وطَرقُ الأبواب، وتحصيلُ الديون، والسحوبات، وإعادةُ بيع
  التذاكر) **لا يمسّ أيٌّ منها التسعيرَ المرجعيَّ ولا مقارنةَ «كان/الآن»**.
  [gov.uk — CMA207](https://www.gov.uk/government/publications/unfair-commercial-practices-cma207)

**النتيجةُ المُصاغةُ بأمانة:** لم أعثر على مدّةٍ رقميّةٍ منصوصةٍ في المملكة المتّحدة.
والظاهرُ أنّ الأمرَ متروكٌ للحظر العامّ على «الأفعال المضلِّلة» تحت DMCC 2024 — أي
معيارٌ نوعيٌّ لا عدديّ، بخلاف الاتّحاد الأوروبيّ.

> **حدُّ التحقُّق:** إرشادُ CMA207 الكاملُ ملفُّ PDF من **64 صفحة**
> (`Unfair_commercial_practices_CMA207_18_Nov_2025.pdf`) **لم أقرأه**. وقاعدةُ
> الثمانيةِ والعشرين يوماً التي تشيع في المراجع البريطانيّة أصلُها دليلُ
> BIS/«Pricing Practices Guide» وهو إرشادٌ غيرُ تشريعيٍّ سُحب. **غيابُ المصدر ليس
> إثباتَ غيابِ القاعدة** — الادّعاءُ هنا هو أنّي لم أجدها، لا أنّها معدومة.

### السعوديّة — **نعم، بترخيصٍ مسبقٍ وبيانِ السعرين**

وزارةُ التجارة، ضمن «9 ضوابط للتخفيضات التجارية في المنشآت والمتاجر الإلكترونية»:

1. «حصول المنشأة أو المتجر الإلكتروني على **ترخيص** لإجراء التخفيضات **قبل الإعلان
   عنها**»
2. إبراز الترخيص ليتحقّق المستهلك عبر الباركود
3. «الالتزام بالعروض والتخفيضات **الحقيقية** المرخّص لها وعدم **التحايل أو التضليل**»
4. «إيضاح **نسبة التخفيض** بحيث تكون محدَّدة ومكتوبة بشكل واضح»
5. «وضع بطاقة الأسعار على المنتجات المخفَّضة و**بيان السعر قبل وبعد التخفيض**»

والضوابطُ تسري على **المتاجر الإلكترونيّة كما تسري على المحلّات**.

المصدر: [وزارة التجارة — 9 ضوابط للتخفيضات التجارية](https://mc.gov.sa/ar/mediacenter/News/Pages/28-02-24-01.aspx)

فالسعوديّةُ توجب **بيانَ السعر قبل التخفيض** وتُحرِّم **التلاعبَ** — لكنّها في هذا
النصّ **لا تُحدّد مدّةً** يجب أن يكون السعرُ الأصليُّ سارياً خلالها.

> **غيرُ متحقَّق:** ظهرت في نتائج البحث عبارةٌ منسوبةٌ إلى الوزارة بأنّ «المعدَّل
> العامَّ للتخفيضات يجب ألّا يقلَّ عن **10%** من السعر **خلال الشهر السابق** لبدء
> التخفيضات» — وهي، إن صحّت، **مرجعٌ زمنيٌّ للسعر الأصليّ يشبه مادّةَ 6a**
> الأوروبيّة. لكنّ الصفحاتِ الحاملةَ لها رجعت **404** (`MerchantGuide/Discounts`،
> و`CustomerGuide/MCI_Offers`)، وملفَّ `Sales-Licensing.pdf` رجع **404** كذلك.
> **لا أُثبِتُها.** من يحتاجها فليطلبها من نصّ لائحة تراخيص التخفيضات مباشرةً.

### الإمارات — **غيرُ متحقَّق**

## ٧. Salla — تلخيصُ ما حُسِم سابقاً (ليقومَ الملفُّ وحدَه)

مصادر: مستودعُ `SallaApp/theme-raed` عند `e273ad2` · حزمةُ
`@salla.sa/twilight-components@2.14.573` · `SallaApp/twilight-i18n` · `docs.salla.dev`.

- **الحقول**: `regular_price` / `sale_price` مع رايةٍ صريحة `is_on_sale`. **لا وجودَ
  لـ`compare_at_price`.**
- **الحارسُ في المتصفّح** فوق رايةِ الخادم:
  `is_on_sale = data.has_sale_price && data.regular_price > data.price;`
- **التاريخ**: الحقلُ اسمُه **`discount_ends`**. و«`sale_end`» **لا وجودَ له** في أيّ
  مصدرٍ أوّليّ. والعدّادُ يظهر على بطاقة الصفحة الرئيسيّة المميَّزة وحدَها، **لا على
  صفحة المنتج**.
- **الألوان**: المشطوبُ **رماديّ** (gray-400 في المكوّن الرسميّ، `text-gray-500` في
  صفحة المنتج)، والمخفَّضُ **أحمر** (`text-red-800`). الشطبُ بـ`line-through`.
- **الترتيبُ في DOM**: المخفَّضُ أوّلاً ثمّ المشطوب — فتحت `dir="rtl"` يقع الجديدُ
  يميناً.
- **الشارة**: نسبةٌ مئويّةٌ دائماً، **لا مبلغَ توفيرٍ أبداً**:
  `Math.round((1 - product.sale_price / product.regular_price) * 100)` بحارس
  `percent > 0`، ومفتاحُ الترجمة `pages.products.discount` = «خصم».
- وتتعايش عندها **شارتان**: المحسوبةُ من النسبة، و`promotion_title` نصّاً حرّاً يكتبه
  التاجر (نظيرُ `StoreCollection.badge_text` عندنا).
- **فجوة**: `SallaApp/twilight` و`twilight-components` غيرُ عامَّين (404)؛ دليلُ
  المكوّنات ناتجٌ مُصرَّفٌ من npm فلا رابطَ ويب دائمٌ لأسطره.

## ٨. التوصيةُ لعقدنا

مصمَّمةٌ على قرار المالك: عرضٌ لا إلزام، حملةٌ بتاريخَين، مشطوبٌ + أحمر.

### الحقول

| المفتاح | النوع | الدلالة | مخزَّنٌ أم مشتقّ |
|---|---|---|---|
| `price` | decimal | السعرُ النافذُ الوحيد — وهو الملزِمُ للفوترة | كما هو اليوم |
| `compare_at_price` | decimal, nullable | الأصليُّ المشطوب، للعرض حصراً | من الحملة |
| `on_sale` | boolean | **للقراءة فقط** | **مشتقٌّ دائماً** |
| `discount_percentage` | int, nullable | يُرسَل فقط حين يكون موجباً | مشتقّ |
| `sale_ends_at` | datetime, nullable | هدفُ العدّاد | من الحملة |

**لماذا `compare_at_price` لا `regular_price`؟** لأنّ `regular_price` تفترض أنّ
`price` مشتقٌّ منها ومن `sale_price` — وهذا **كاذبٌ عندنا**، إذ خصمُنا لا يمسّ
`price` إطلاقاً. أمّا «compare at» فاسمٌ لا يحمل أيَّ إيحاءٍ بالإلزام، وهو الدقيقُ
لحقلِ عرضٍ صِرف. **لكنّ هذا قرارُ مالك**: إن كان جمهورُ التجّار سلَّاويَّ الخلفيّة
فقد يكون `regular_price` أقربَ إلى ألفتهم.

**قاعدةُ الاشتقاق** — تقاطعُ حرّاس المنصّات الثلاث، بلا زيادة:

```
on_sale = compare_at_price is not None
          and compare_at_price > price
          and starts_at <= now <= ends_at
```

وثلاثةُ قيودٍ تلازمها:

1. **لا يُرسَل `compare_at_price` قطُّ حين `on_sale` كاذبة.** المنصّتان تُبقيان القيمةَ
   مخزَّنةً لكنّ مسارَ الرسم لا يقرؤها إلّا تحت الحارس؛ وإرسالُها مكشوفةً يُغري
   عميلاً بشطبٍ كاذب.
2. **لا يُحذَف المخزَّنُ عند انتهاء الحملة** — أُسوةً بـWooCommerce: النافذةُ تُقيَّم
   عند القراءة، والحملةُ المنتهيةُ تبقى سجلّاً.
3. **الاشتقاقُ في دالّةٍ واحدة** لا شرطاً منثوراً في المُسلسِلات — WooCommerce نفسُها
   تجعله نقطةَ سياسةٍ واحدةً قابلةً للتجاوز بمرشّح.

**التاريخان:** أوصي بكشف **الانتهاء وحدَه** على العقد العامّ (`sale_ends_at`) وإبقاءِ
البدء داخليّاً — الواجهةُ لا تحتاج غيرَ هدفِ العدّاد، وSalla تكشف `discount_ends`
وحدَه كذلك. (WooCommerce تكشف الاثنين، وShopify لا تكشف شيئاً.) **قرارُ مالك.**

### العرض

- **الأحمرُ للمخفَّض، والرماديُّ للمشطوب** — العُرفُ الوحيدُ المُسنَد (Salla)، وWoo
  وShopify لا تفرضان لوناً.
- **الترميزُ `<del>`/`<ins>` مع `aria-hidden="true"` ونصٍّ لقارئ الشاشة**، على نمط
  WooCommerce — أفضلُ من شطبِ CSS العاري بلا ثمن.
- **ترتيبُ DOM**: أرجّح نمطَ Salla (المخفَّضُ أوّلاً) لواجهةٍ RTL. **خلافٌ بين
  المنصّتين ⇒ قرارُ مالك.**
- **الشارةُ نسبةٌ لا مبلغَ توفير**، وتُسقَط عند الصفر.

### قاعدةُ الغلبة — قرارُ مالكٍ لا نتيجةُ بحث

لا سابقةَ تُنقَل. أُرشِّح مبدأ Shopify: **الأعمقُ خصماً يفوز، ويُحسَم في الخادم،
ويُرسَل الفائزُ وحدَه**. وأُسجّلها **قرارَنا** مستنِداً إلى مبدأ Shopify العامّ في
الخصومات المُلزِمة — لا بوصفها قاعدةً موثَّقةً في أسعار العرض، فتلك غيرُ موجودة.

### تحذيرٌ يستحقّ حقلاً الآن

خصمُنا اليومَ **رقمٌ يكتبه التاجر**. هذا يكفي ضوابطَ السعوديّة **بالثقة** (فهي توجب
البيانَ والصدقَ ولا تنصّ مدّةً في المصدر الذي فتحتُه)، **ولا يكفي المادّةَ 6a
الأوروبيّة** التي توجب أن يكون المشطوبُ **أدنى سعرٍ فُرِض فعلاً خلال 30 يوماً**.

فإن كان ثمّة احتمالٌ لخدمة سوقٍ أوروبيّة، فالفرقُ ليس تنسيقاً بل **جدولَ تاريخِ
أسعارٍ لا نملكه**. والتحوّطُ رخيصٌ اليومَ وباهظٌ لاحقاً: **تسجيلُ طوابعِ تغيُّر السعر
من أوّل يومٍ حتّى لو لم تُستعمَل** — فتاريخُ الأسعار **لا يُستعاد بأثرٍ رجعيّ**.
قرارُ مالك: (أ) السوقُ خليجيٌّ حصراً فيُقبَل الأصليُّ المكتوب، أو (ب) نُسجّل التاريخَ
من الآن.

## ٩. ما لم يُغطَّ

- **Zid** و**BigCommerce** — خارجَ نطاق هذه الجولة بقرارٍ مسبق.
- **نصُّ EUR-Lex التشريعيّ** للمادّة 6a — رجع فارغاً؛ الاعتمادُ على `europa.eu`.

  السابق» **غيرُ مثبَتة**.
- **التشريعُ الإماراتيّ** — 403.
- **الأردنّ وفلسطين** — لم يُبحَثا.
- **مسارُ احتساب كوبون WooCommerce** فوقَ السعر المخفَّض — استُدلَّ عليه ولم يُفتَح.
- **معالجةُ Shopify البصريّة** — لا مصدرَ أوّليّ (مسارُ توثيق القوالب 404).
